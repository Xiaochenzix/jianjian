# 剪剪 v0.1 已确认需求

用户确认后开始开发。需求讨论和实现保持分离；新增重大功能或改变既定行为，应先讨论确认。

| 项目 | 需求 |
| --- | --- |
| 名称 | 剪剪，暂定 |
| 平台 | Android、Windows、macOS、Linux，不含 iPhone |
| 使用范围 | 同一账号自己的设备之间互通；账号之间隔离，不做跨用户聊天 |
| 部署 | 用户自己的服务器 |
| 账号 | 第一版支持多用户，管理员创建，不开放公开注册 |
| 时间线 | 统一展示消息、剪贴板和文件，标注来源设备 |
| 剪贴板 | 文字和链接，不含图片 |
| 开关 | 每台设备独立控制自动发送剪贴板、自动写入本机剪贴板；都有手动复制入口 |
| 系统识别 | 自动识别设备和系统能力；不支持时必须显示原因，不显示虚假的可用状态 |
| 历史 | 服务端保存，重新上线补同步，可手动删除 |
| 文件 | 自动显示记录，点击下载；默认保存 7 天、上限 500 MB，管理员可调整 |
| 运行 | 电脑托盘与开机启动；手机后台接收、显示连接状态 |

补充实现约定：自动开关默认关闭；仅实时收到的其他设备新文字可自动写入，历史补同步不覆盖当前剪贴板；自动写入与手动复制不会触发循环回传。服务端默认每用户 5 GB 文件额度并预留磁盘空间，额度可调整。当前未加入端到端加密。

Android 10+ 后台读取剪贴板受系统限制：自动识别并说明，前台监听和回到应用同步；后台接收与后台读取能力分开呈现。锁屏后台读取不作为普通 Android 应用已经实现的能力。

## 2026-10-04 界面修订

用户选择微信式消息聊天布局，并反馈 Android 存在内容被遮挡的问题。v0.2 将消息按旧到新从上至下排列，最新在底部；显示左右气泡及来源设备。手机提供消息、设备、设置入口，聊天区独立滚动，输入栏随键盘缩放。原生容器统一处理系统栏、刘海及键盘安全区。加载历史和收到新消息不应打断正在阅读的位置。

## 2026-10-04 Windows 悬浮窗（已确认）

用户确认本轮只做 Windows 常驻置顶小消息窗，可拖动、调整大小并记住位置；复用主界面账号和消息，标注设备及时间，滚动查看最近记录，实时接收、一键复制、输入发送，Enter 发送、Shift+Enter 换行。文件卡片回主界面处理。主界面与托盘均可开启；关闭小窗不停止后台同步，断网自动重连，沿用现有剪贴板开关。实现保留最近 50 条，完整历史仍在主界面；退出账号会清空并关闭小窗。
